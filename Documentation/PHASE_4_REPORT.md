# Duo Angle — Phase 4 目标角度管理报告

日期：2026-10-17 咩。

## 实现摘要

Phase 4 已加入可持久保存的目标角度、原生列表和滚轮编辑器，支持新增、编辑、删除与分别启停咩。
测量、`ArrangementView`、主界面底栏和支持开发页面的既有流程保持原有结构咩。
本阶段没有加入目标监控、到达提醒、相机采集或 StoreKit 功能咩。

## 数据模型与持久化

`AngleTarget` 使用稳定 UUID、整数角度和启用状态，角度范围集中定义为 `0...180`，新增默认值为 90° 且默认启用咩。
`AngleTargetStore` 是应用启动时创建并共享的 Observation 数据源，使用 Codable 与 UserDefaults 保存目标数组，所有变更即时更新列表并写入存储咩。
目标按角度升序排列，重复角度无论是否启用均不允许，编辑时排除自身并保留 UUID 与原启用状态咩。
相同角度或相同启用状态的无变化操作不会写入存储咩。
解码失败、存储类型异常、重复 UUID、重复角度和范围外数据均视为损坏；原始数据保留，写入被阻止，只有用户确认重置后才清除咩。
UI 测试使用独立 UserDefaults suite，启动时清空该测试域，不会修改正常应用的目标数据咩。

## 设置页与滚轮编辑器

“设定角度”使用系统 List、Toggle、滑动删除及长按菜单删除，空状态提供添加入口，导航栏提供“完成”和加号咩。
列表显示当前已启用数量，修改开关无需另行保存咩。
新增与编辑共用 `AddAngleView`，使用系统 `.wheel` Picker 逐度选择 0° 至 180°，可取消或保存咩。
重复角度会显示内联提示并禁用保存，存储层再次校验范围和重复性咩。
大号预览使用 `.numericText()` 与 0.12 秒动画，Reduce Motion 开启时改用无数字过渡的路径咩。
滚轮沿用系统自身的选择反馈，没有额外叠加每格触觉；模拟器无法核验实体触觉强度咩。
VoiceOver 可读取编辑按钮、目标开关、选定角度及保存和取消，删除还可通过上下文菜单操作咩。

## 使用当前角度

编辑器读取 `MainView` 已在使用的 `HingeMeasurementManager`，没有新增传感器观察者或模拟读数咩。
`CurrentAngleSelection` 使用现有 `AngleMath` 换算弧度，四舍五入到整数，并仅在状态为部分展开或完全展开、读数有效且最近回调距今不超过 10 秒时提供快捷填入咩。
闭合、未知、不可用、范围外或过期时按钮禁用并显示“当前角度不可用”，手动滚轮始终可用咩。
模拟器从部分展开切到完全展开时，Sheet 中的实时回调使该按钮可用，点击后滚轮和预览从 90° 变为真实模拟器读数 180° 咩。
系统在静止姿态可能不持续发送回调，因此超过有效期后按钮会禁用，这是防止把旧快照误称为当前角度的安全退路咩。

## Camera Control 可行性

iOS 27.1 SDK 的 `AVKit/AVCaptureEventInteraction.h` 明确写明该 API 只能用于拍摄场景，系统只向正在使用相机的应用发送拍摄事件咩。
公开的 `AVCaptureEvent` 提供按压阶段，而没有为普通非相机编辑页验证到滑动位移输入咩。
**Camera Control adjustment is not implemented because no suitable public non-camera input API was verified.** 咩。
应用没有开启 AVCaptureSession、请求相机权限或调用私有 API 咩。

## 测试与构建

Xcode MCP 在 iPhone Duo / iOS 27.1 模拟器上完成 Debug 构建与运行、Release 构建，均成功咩。
完整测试套件通过 19 项，失败 0 项，跳过 0 项，包含原有测试、7 项目标数据测试及目标管理 UI 流程测试咩。
定向 UI 测试覆盖打开空状态、新增与保存、滚轮改值、取消、编辑保存、开关和滑动删除咩。
单元测试覆盖边界、重复、排序、稳定身份、持久化往返、损坏数据和当前读数有效期咩。
测试工具结束后曾把 iPhone Duo 模拟器关机，已用 Xcode MCP 重新开机；后续未再运行测试，最终交付时保持模拟器开机咩。

## 模拟器观察与限制

浅色闭合姿态的新增页显示系统滚轮和不可用提示，深色完全展开姿态显示语义化深色背景、180° 预览和可用的当前角度按钮咩。
滚轮 90°→91°、保存、取消、启停和滑动删除由 UI 自动化验证；多个目标的排序及去重由单元测试验证咩。
真实设备上的连续折叠、触觉、VoiceOver 全流程、极大 Dynamic Type、显示区域迁移与物理读数精度仍需实机验收咩。
既有 fullyOpen→partiallyOpen 读数迁移延迟仍未解决，本阶段未修改该布局机制咩。

## Phase 5 接入准备

后续监控器可以直接观察 `AngleTargetStore.enabledTargets`，再实现角度跨越、容差与滞后、目标到达触觉等逻辑咩。
当前的滚轮选择触觉与未来的目标到达提醒是两种不同交互，Phase 4 未实现后者咩。
