# Duo Angle Phase 7B.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prepare Duo Angle for public release with five-language localization, accurate privacy materials, safe icon variants, the new developer team, and the existing public GitHub repository.

**Architecture:** Preserve the current SwiftUI, hinge measurement, target monitoring, persistence, haptics, and StoreKit boundaries. Add localization through Apple's String Catalog, prepare privacy and project documentation from code inspection, configure the supplied artwork in the existing asset catalog, and update signing only after validating the new team's exact Team ID and provisioning readiness.

**Tech Stack:** SwiftUI, StoreKit 2, Apple String Catalog (`.xcstrings`), Xcode Asset Catalog, Xcode MCP, Git/GitHub.

**Spec:** `Documentation/superpowers/specs/2026-10-17-phase-7b-1-design.md`

## Global Constraints

- Preserve all existing measurement, layout, target-monitoring, persistence, haptics, and StoreKit architecture.
- Support `zh-Hans`, `zh-Hant`, `en`, `ja`, and `ko` using system language preferences; do not add an in-app language selector.
- Keep Bundle Identifier `com.TNTstudio.DuoAngle` and StoreKit Product ID `com.TNTstudio.DuoAngle.support.coffee` unchanged.
- Do not alter identifiers merely to make signing or compilation succeed; if the new team's App ID, signing, or Provisioning Profile is unavailable, record the blocker.
- Preserve the supplied dark icon and central symbol; the light variant may change only palette and material treatment.
- Inspect alpha edges, corner treatment, and asset-catalog configuration for halos, white borders, clipping, or duplicated rounding.
- Inspect the complete Git history and working tree for API keys, certificates/private keys, sensitive configuration, and user files before any public push; if risk is found, stop the public push and do not rewrite history.
- Keep the existing working-tree changes and untracked files intact; stage only intended Phase 7B.1 changes.
- Do not run the full regression suite, do not perform unrelated refactoring, and do not shut down the Simulator after any check.
- Use Xcode MCP for Xcode project, build, and Simulator operations; do not make real-money purchases or claim physical-device validation.
- Produce one final commit named `chore: prepare Duo Angle for public release`; push only after security checks pass.

## Review Focus

- Translation placeholders and plural counts — inspect the catalog format strings and compile both app configurations.
- Small/large text in compact Duo arrangements — check key screens at the existing/default and accessibility text sizes through targeted UI inspection.
- Alpha fringe and icon masking — inspect source/final pixels and asset-catalog entries, then inspect the installed app icon in Simulator.
- Team migration entitlements — verify the intended new Team ID, existing Bundle ID/Product ID, App ID, signing, and profile without substituting identifiers.
- Public-history exposure — scan all commits and staged/unstaged/untracked files; any credential-like finding halts public push pending remediation instructions.
